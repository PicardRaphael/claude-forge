# Schema Context

## Project paths

| Resource | Path | Description |
|---|---|---|
| PostgreSQL functions repo | Configured in CLAUDE.md | READ-ONLY. Contains all `f_*`, `p_*`, `proc_*`, `tr_*` functions |
| Schema documentation | `doc/schemas/` | Generated by schema-mapper. One file per domain. |
| Table CSV exports | `doc/dump/` | Exported by `export-schema.sh`. Column definitions + sample data. |
| Migration tracker | `doc/migration-tracker.md` | Tracks which PG functions have been migrated |

## How to set up

In `CLAUDE.md`, set the absolute path to the PostgreSQL functions repo:
```markdown
## Config
- Repo fonctions PostgreSQL : /absolute/path/to/pg-functions-repo
```

## Reading the schema

### Option 1 — Read doc/schemas/ files (preferred)
Generated by schema-mapper. Human-readable, domain-organized.
```
doc/schemas/
├── coproprietes.md    # Copropriétés table + relationships
├── lots.md            # Lots + tantiemes tables
├── comptabilite.md    # Comptes + écritures tables
└── ...
```

### Option 2 — Read doc/dump/ CSV files
Raw column definitions from PostgreSQL `information_schema`.
```
doc/dump/
├── coproprietes.csv   # All columns: name, type, nullable, default
├── lots.csv
└── ...
```

### Option 3 — MCP PostgreSQL (if configured)
See `schema-data-source/SKILL.md` for MCP query patterns.

## Table naming conventions in this database

- All tables: `snake_case`, plural (e.g., `coproprietes`, `appels_de_fonds`)
- Primary keys: `id` (integer or uuid depending on table age)
- Foreign keys: `[referenced_table_singular]_id` (e.g., `copropriete_id`)
- Timestamps: `created_at`, `updated_at` (not always present)
- Soft delete: `deleted_at` (nullable, not all tables)

## Drizzle schema location

Drizzle table schemas (introspected from DB) live in:
```
src/infra/postgres/schema/
├── coproprietes.table.ts
├── lots.table.ts
├── index.ts            ← re-exports all tables
```

Run `bun run db:pull` to re-introspect the database and update these files.

## Important: never modify the PG functions repo

The PostgreSQL functions repo is a **read-only reference**.
It documents the existing business logic that is being migrated.
Any modification to PostgreSQL functions must go through the DBA, not Claude.
