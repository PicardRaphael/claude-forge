# Task

## ID

project-brainstorm

## Type

FEATURE

## Title

Global Codex project-brainstorm pipeline

## Done

The three specialized Codex agents, their global orchestration Skill, isolated cognition profiles, versioned handoffs, installer, documentation, and runtime checks are implemented and verified from two clean repositories, with a compatible handoff into the existing Codex development workflow.

## Confirmed user intent

Create a Codex-native global pipeline:

`cdc_brainstorm -> architect_brainstorm -> review_brainstorm`

This is not a Claude Code installation. Reuse the existing Codex development workflow (`change-delivery-workflow` plus `architect_feature_bug`, `lead_developer`, and `reviewer_feature_bug`) as the downstream delivery system instead of creating a competing development workflow.

## Expected outcome

- Canonical sources live under `global-config/codex/`.
- Active global agents live under `~/.codex/agents/*.toml`.
- The global orchestration Skill lives under `~/.agents/skills/project-brainstorm/`.
- Secure role execution uses one independently authenticated `~/.codex-project-brainstorm/` runtime with apps/plugins disabled and exactly one role MCP enabled per child process.
- Native invocation is `$project-brainstorm` or selection through `/skills`. Codex does not document `/project-brainstorm` as a native custom command alias.
- Dedicated product, architect, reviewer, and curator MCP profiles use the existing `mcp-forge-cognition` server and `cognition-store` through absolute paths.
- A compatible verdict creates an immutable `development_handoff` consumable by the existing DEV workflow; no product code is generated by brainstorming agents.

## Constraints

- Preserve all existing user changes, including `.codex/config.toml` and untracked Codex agents/Skills.
- Do not replace or modify the existing development workflow unless a minimal compatibility bridge is required.
- Do not create a second MCP, duplicate cognition storage, migrate forge-brain, or use symlinks by default.
- The main Codex task orchestrates. Brainstorm agents do not spawn agents.
- Set all three agents to `sandbox_mode = "read-only"`; their durable writes go only through their scoped MCP profile.
- Option A is confirmed: global agent TOMLs are fail-closed dispatch descriptors; project content is processed only by the isolated runtime, never by a native subagent inheriting the parent tool inventory.
- No cognition profile receives wildcard project access. Access is granted by project, artifact series, role, and current revision.
- Curator capability is never exposed to the three brainstorm agents.
- Human CDC approval is enforced server-side before architecture access.
- Reviewer receives a structurally neutralized packet and cannot read product or architect private memory.
- Revisions are append-only and content-hashed; stale reviews cannot authorize newer inputs.
- After two consecutive reworks, the service requires a curator-recorded human decision.
- Installer operations are manifest-driven, conflict-aware, idempotent, backed up, and transactional.
- Use system home APIs; do not hard-code a username in source or generated configuration.

- Global Codex DEV Skill: `~/.codex/skills/change-delivery-workflow/`.
- Historical architecture prompt at Git commit `23e1fda...`, used for evidence-first repository analysis, alternatives, components, data, APIs, security, tests, deployment, and readiness while removing stack-specific coupling.
- Existing `mcp-forge-cognition`, `cognition-store`, principals, service, ACL model, MCP presentation, schemas, and tests.

## Acceptance criteria

- AC-001: Three canonical and active global Codex TOML agent profiles exist, parse, and are discoverable.
- AC-002: The global `$project-brainstorm` Skill is concise, discoverable, and orchestrates only the brainstorming state machine.
- AC-003: Four global Codex MCP profiles start from any working directory using absolute server/store paths and exact role-specific tool allowlists.
- AC-003A: The user's main `.codex/config.toml` is not mutated; runtime fails closed until a compatible CLI and the separate one-time Codex login are verified.
- AC-004: Private namespace isolation holds for search, list, and direct-ID access without existence leaks.
- AC-005: Strict versioned schemas validate CDC, architecture, review packet, review verdict, and development handoff; revisions are immutable and hash-consistent.
- AC-006: Human approval, all six verdicts, targeted rework, stale-revision rejection, and the two-rework human gate are enforced server-side.
- AC-007: Installer check/install/update/uninstall is idempotent, conflict-aware, recoverable, and does not delete unmanaged files or silently rewrite unrelated Codex configuration.
- AC-008: The final handoff explicitly bridges into `change-delivery-workflow` without invoking development agents.
- AC-009: Visibility and MCP availability are verified from two clean repositories plus a local-masking fixture; a bounded fresh-process Codex smoke test reaches development handoff.
- AC-009A: Downgrade disables role entry points before older cognition code can serve a store containing pipeline-managed documents.
- AC-010: Unit, integration, ACL, neutralization, installer, and regression tests pass; independent plan and code reviews pass.
