# Memory and learning model

Documents distinguish semantic, episodic, procedural and calibration memory. Every document has immutable identity, versioned schema, provenance, confidence basis, lifecycle status, revision and content hash. Updates create a new revision; outcomes have no update path and the domain rejects revision attempts.

Hypotheses require evidence before validation. Shared memories originate in an inbox and can only be validated/rejected/restricted by Curator. Supersession updates both sides of the relation atomically. Physical deletion is not a business operation.

The learning cycle is execution → private episode → observed outcome → retrospective → candidate lesson → contradiction search → Curator decision → versioned procedure → reuse → measurement → restriction/deprecation.

Normal procedure promotion requires three independent episodes, at least two projects/contexts, one real outcome, counterexample/contradiction search and Curator validation. A severe incident may create a time-bounded `restricted` procedure with expiry, mandatory review, evidence level and incident ID.

Enthusiasm, idea selection, LLM rating, a liked brief or architecture handoff are not outcomes. Calibration returns `null` when no real outcome exists.
