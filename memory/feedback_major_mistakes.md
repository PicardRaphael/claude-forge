Cf [[erreur-advisory-rules-insuffisantes]] (doctrine : les rules "OBLIGATOIRE" sont ignorées sous pression — fluency bias). Couvre la cause racine des cas #7/#8/#9 ci-dessous.

**Cas empirique(s) :**

- **#1 — Agent CTO orchestrateur** : créé un agent CTO censé déléguer aux autres agents. À l'époque un subagent ne pouvait PAS spawner de sub-agents (GitHub #19077 — prémisse PÉRIMÉE : nesting possible depuis v2.1.172, depth 3 par défaut depuis v2.1.219). Avec outils → fait le travail lui-même ; sans outils → ne fonctionne pas. Correction : la session principale orchestre, routing dans rules — recommandation toujours valide (escalade > nesting, cf [[anti-reentrance-sub-agents-pattern-escalade]]). Leçon : vérifier les limitations techniques AVANT de concevoir.
- **#2 — Routing dans CLAUDE.md** : workflow agents, tableaux de triage, compétences CTO mis dans CLAUDE.md. CLAUDE.md = contexte projet (config, standards, conventions) ; le routing et les comportements obligatoires vont dans `.claude/rules/`. Correction : `rules/agent-delegation.md`, `rules/cto-mindset.md`, `rules/skill-navigator.md`, `rules/database-rules.md`. Leçon : regarder les projets existants AVANT de proposer une architecture.
- **#3 — Pas regardé neo_ia existant** : inventé une architecture sans regarder les patterns en place. neo_ia avait déjà la bonne structure (rules/, agents/, skills/, commands/, hooks/, scripts/). Leçon : toujours demander "tu as un projet existant que je peux regarder ?" en début de session.
- **#4 — Testé 5 fois le CTO au lieu de chercher la vraie solution** : retiré Bash → Grep → Read → Glob un par un au lieu de comprendre le problème fondamental (la doc disait clairement, à l'époque, que les subagents ne pouvaient pas spawner — périmé depuis v2.1.172, cf #1). Leçon : quand un fix ne marche pas, RECHERCHER la cause racine au lieu de bricoler.
- **#5 — Plugin externe au lieu des skills forge** : invoqué `plugin-dev:plugin-structure` (qui mentionnait `commands/` déprécié) au lieu de consulter mémoire + `cc-cowork-ref`. Ordre : mémoire → skills forge → plugins externes (dernier recours). Leçon : les skills forge sont la source canonique ; les plugins externes peuvent avoir des infos obsolètes.
- **#6 — Mauvais format de permissions Bash propagé partout** : utilisé `Bash(git commit:*)` avec `:` au lieu de `Bash(git commit *)` avec espace dans 9 fichiers settings.json sur 6 projets (claude-forge, ia_back, neo_ia, neoteem-brain, bdd, neopsql, neoauth). Aucune permission Bash ne marchait silencieusement → Claude demandait permission à chaque commande. Format correct = `Bash(command_prefix *)` avec ESPACE. Leçon : vérifier la doc/le web AVANT de copier un format dans plusieurs fichiers — une erreur de syntaxe propagée = dette x nombre de fichiers.
- **#7 — 4 skills créées sans consulter forge-brain ni cc-skills-ref** : backlog-triage, strategic-advisor, prompt-boost, daily-pilot créées sans lire le vault ni charger cc-skills-ref. Descriptions YAML bourrées de triggers FR entre guillemets ("Use when the user says X, Y, Z"). Raphael a dû corriger ; descriptions réécrites en triggers sémantiques anglais ; erreur documentée dans vault Knowledge/erreurs/.
- **#8 — Toutes les rules ignorées lors d'une analyse complète (ia_back, 2026-04-26)** : 4 rules ignorées (check-before-create, delegate-to-specialists, forge-brain-proactive, memory-discipline) ; 6 skills modifiées + 14 agents modifiés à la main sans aucun agent spécialisé, zéro consultation vault/mémoire. Tout le travail à refaire. Correction : hook déterministe `delegate-guard.py` (bloque Edit/Write sur SKILL.md, agents/*.md, CLAUDE.md).
- **#9 — 3 notes vault créées sans consulter le vault (2026-05-06)** : agentic-engineering-karpathy, neoteem-mapping, pattern-agentic créées sans lire Knowledge/erreurs/ ni 04-Techniques/ ni feedbacks mémoire. Même pattern que #7/#8 mais sur notes vault. Leçon : consulter le vault AVANT de créer une note, comme pour skills/agents.
