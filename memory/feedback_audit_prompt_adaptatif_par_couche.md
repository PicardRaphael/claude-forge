Quand on audite la sur-spécification (S*=0.509) d'un système de prompts à **architecture adaptative** (type AdaptivePromptBuilderV2 de neo_ia : Layer 1 core + Layer 2 task + Layer 3a tool instructions + Layer 3b response templates), ne JAMAIS scorer un fichier `prompts.py` comme un bloc unique. Scorer **par couche**, avec un budget de spécification pondéré par le **statut de chargement** :

- **Core/Task (toujours chargé, à chaque requête + doit rester caché)** → budget STRICT. C'est là que la sur-spec coûte le plus (concision 3.5 + cache).
- **Layer 3a (INSTRUCTION d'un tool, chargé UNIQUEMENT si le tool est sélectionné par le Tool RAG)** → budget tolérant. Ex : les 23 `<must>`/`<forbidden>` de `lister_donnees` ne polluent pas les autres requêtes — elles n'apparaissent que quand le tool est actif. Moins grave qu'en bloc plat, mais compte quand même pour l'appel où le tool est chargé.
- **Layer 3b (RESPONSE_FORMAT, synthèse)** → budget tolérant.

**Why:** consigne explicite Raphael (26 juin 2026) — « j'aimerais vraiment que les skills correspondent à notre architecture de prompt […] ne pas perdre cette architecture poussée ». Un audit naïf qui dirait « lister_donnees a trop de contraintes, coupe » casserait justement l'intérêt de l'archi en couches (injecter ces contraintes à la demande via `conditional_rules`/ToolPromptLoader). Aplatir = category error.

**How to apply:** avant de concevoir un audit de prompts, lire le `builder.py` réel pour savoir quels prompts sont CORE (toujours là) vs ADAPTATIFS (à la demande), distinguer agents simples (system prompt plat : reformulation, devis) vs agents adaptatifs (Universal, NeoMail, Lojii, Support). Archi canonique : [[neochat-adaptive-prompt]]. Doctrine sur-spec : [[over-specification-paradox]] + [[deprecated-techniques-2026]].

**Corollaire « audit par script = fausse précision » (26 juin) :** un script qui COMPTE (balises `<must>`, longueur, « tool dans `_disabled/` = mort ») donne une fausse précision et produit des faux positifs/négatifs. Vécu sur audit-prompts neo_ia : 3 inventaires faux successifs (ratait builder.py, NeoDoc, prompts inline/minuscules) + un faux P1 (classait un `conditional_rule` chargé à la demande comme toujours-chargé) + un faux « réf morte » (`creer_brouillon`/`appliquer_label` sont dans `_disabled/` MAIS utilisés délibérément par NeoMail — prouvé par `test_disabled_tools_availability.py`). Décision Raphael : skill `audit-prompts` SANS script, pure checklist de lecture (LLM lit chaque prompt en entier + lit le `blueprint.py` pour le statut de chargement réel + juge par couche avec la doctrine). **Leçon transférable : `_disabled/` ≠ mort pour tous les agents ; vérifier l'usage réel (tools.py + tests) avant de déclarer une réf morte. Compter ≠ juger.** Cf [[feedback_verify_exhaustive_claims]] + [[feedback_diagnostic_empirique_avant_affirmer_garde]].

**Corollaire fusion skills (26 juin) :** neo_ia est 100% Gemini (36× ChatGoogleGenerativeAI, zéro autre provider — vérifié). Garder une skill `prompt-engineering` model-agnostic SÉPARÉE d'une skill `gemini-prompting` était une frontière théorique sans usage réel (les deux se chargeaient toujours ensemble) → fusionnées en UNE skill `gemini-prompting`. Piège que j'ai failli commettre : défendre la séparation par « le jour où un non-Gemini arrive » = feature spéculative interdite (CLAUDE.md « code minimum »). Et anti-pattern de raisonnement : j'avais justifié la fusion par « prompt-engineering jamais seule » alors que mon propre grep montrait architect-deep/codebase-analyst la chargeant seule — l'advisor a rattrapé la contradiction (cf [[feedback_brief_premisse_fausse_verifier_avant_executer]]). La VRAIE raison : en 100% Gemini, même un review de prompt review un prompt Gemini → la frontière universel/Gemini ne sépare aucun usage. **Condition de fusion sûre : body de la skill reste agnostique-VERSION (universel + Gemini stable), tout le version-specific (2.5 vs 3.5 : sampling, thinking_level, cache) en `references/` par axe (modèle × type d'agent ReAct/classif/RAG/créatif).** Le drift à éviter : mettre le même fait version-specific dans le body ET les refs (single-source — refs = foyer).
